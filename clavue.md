## Repository identity

Publishes [`clavue-agent-sdk`](https://www.npmjs.com/package/clavue-agent-sdk):
an in-process TypeScript agent runtime. **Library first, CLI second.** No
daemon, no subprocess — `run()` / `query()` / `createAgent()` execute the full
agent loop inside the host process. Source of truth is `src/`; compiled
`dist/` ships to npm (`package.json#files`) — never hand-edit `dist/`.

- Stack: TypeScript ES2022 + ESM (`NodeNext`), `strict: true`, Node ≥ 18.
- Two CLI bins: `clavue-agent-sdk`, `clavue-agent` → `dist/cli.js`.
- 13 subpath exports: root + `/core`, `/tools`, `/contracts`, `/workflow`,
  `/retro`, `/testing`, `/graph`, `/guardrails`, `/tracing`, `/sandbox`,
  `/rag`, `/genui`, `/voice`.

## High-level architecture

The SDK is layered. When making changes, identify the layer — concerns should
not leak across boundaries.

```
src/index.ts                         # public export surface (vendor-neutral)
  └─ src/agent.ts                    # Agent / createAgent / query / run
  └─ src/cli.ts                      # npx wrapper

src/engine.ts (QueryEngine)          # agentic loop: model call → tools → repeat
  └─ src/engine/*.ts (15 helpers)    # compact, dispatch, retry, results, gates

src/providers/                       # vendor abstraction
  ├─ types.ts                        # LLMProvider, Normalized* contract
  ├─ anthropic.ts, openai.ts         # both implement the interface
  └─ capabilities.ts                 # per-model feature flags

src/tools/                           # 30+ built-in tools, named toolsets
src/skills/  src/hooks.ts  src/mcp/  # extensions plugged into engine

# v3 capability axes (each is also a subpath import)
src/graph/  src/guardrails/  src/tracing/  src/sandbox/
src/rag/    src/genui/       src/voice/    src/runtime/

# Durable / contract layer (host-neutral, keyed by runtimeNamespace)
src/agent-jobs.ts        background AgentJobs + replay
src/issue-workflow.ts    builder/reviewer/fixer/verifier loop
src/workflow-contract.ts WORKFLOW.md parse/render/validate
src/proof-of-work.ts     evidence + gates handoff artifact
src/orchestration-policy.ts  candidate selection, backoff
src/runtime-profiles.ts  collect/organize/plan/solve/build/verify/review/ship
src/memory.ts + memory-policy.ts   structured memory store
src/session.ts           multi-turn persistence
src/retro/               eval/score/compare/loop (deterministic, outside LLM)
src/evaluation-loop.ts   bounded retry with verification
src/improvement.ts       run → memory candidates
src/doctor.ts  src/benchmark.ts   preflight + perf gates
```

### Cross-cutting concerns (read multiple files together)

- **Provider abstraction.** `src/providers/types.ts` defines `LLMProvider`,
  `NormalizedMessageParam`, `NormalizedTool`, `NormalizedResponseBlock`.
  `anthropic.ts` and `openai.ts` both implement it so the engine never
  branches on vendor. `capabilities.ts` decides per-model features (vision,
  Responses API, parallel tools, prompt caching). New model / vendor quirk
  → fix in the provider, **not** in `engine.ts`.

- **Tool registry & toolsets.** `src/tools/index.ts` is the single source for
  `getAllBaseTools()` and the named toolsets (`repo-readonly`, `repo-edit`,
  `research`, `planning`, `tasks`, `automation`, `agents`, `mcp`, `skills`).
  Adding a tool means: register here AND export from `src/index.ts`. Toolset
  membership in `TOOLSETS` must stay in sync with `ToolsetName` in
  `src/types.ts`.

- **Public schema versions in `src/types.ts`.** `SDK_EVENT_SCHEMA_VERSION`,
  `AGENT_RUN_RESULT_SCHEMA_VERSION`, `AGENT_RUN_TRACE_SCHEMA_VERSION`,
  `AGENT_JOB_RECORD_SCHEMA_VERSION`, `MEMORY_TRACE_SCHEMA_VERSION`,
  `CONTROLLED_EXECUTION_CONTRACT_VERSION`, `PROOF_OF_WORK_SCHEMA_VERSION`.
  **Bumping any of these is a breaking change** for downstream hosts. Adding
  optional fields is fine; changed semantics, removed fields, or renamed
  enums require a version bump and a README note.

- **Permission / autonomy / quality gates** are three orthogonal axes:
  - `permissionMode` gates **whether** a tool can run.
  - `autonomyMode` (`supervised`/`proactive`/`autonomous`) gates **how often**
    the agent asks.
  - `qualityGatePolicy` gates **whether a run counts as "completed"**.
  Tool policy enforcement lives in `engine.ts` (allow/deny + `canUseTool` +
  workspace-path containment in file tools). Don't add ad-hoc safety logic
  inside individual tools when the engine layer already handles it.

- **Runtime namespacing.** Background AgentJobs, issue workflows, cron jobs,
  team mailboxes are keyed by `runtimeNamespace` (resolved through
  `src/utils/runtime.ts`). This is what makes the SDK safe to embed in
  multi-tenant hosts. Persisted state goes under `os.tmpdir()` / configured
  dirs partitioned by namespace — never write to a hard-coded location.

- **Workflow modes (`runtime-profiles.ts`).** Eight named modes (`collect`,
  `organize`, `plan`, `solve`, `build`, `verify`, `review`, `ship`) are
  pre-baked combinations of toolset + permission mode + memory policy +
  appendSystemPrompt. Hosts pass `workflowMode: 'verify'` to get the preset.
  `ControlledExecutionContract` is part of the public surface — profile-shape
  changes need a version bump.

- **Retro / eval loop (`src/retro/*`).** Deterministic evaluation that runs
  *outside* the LLM agent loop: evaluators score findings → policy decides
  accept/retry/abandon → ledger persists → optional `runRetroLoop` retries
  with bounded attempts. Composes with `selfImprovement.retro`. When changing
  scoring or dimensions, update `RETRO_DIMENSIONS` in `src/retro/types.ts`
  and the dependent evaluators.

- **Engine helpers.** `engine.ts` is intentionally split into 15 modules
  under `src/engine/` to stay under ~1000 lines. New agent-loop logic →
  extend an existing helper or add a new one; don't inline back into
  `engine.ts`. `npm run bench:engine` enforces the line-count regression
  threshold.

- **Subpath exports.** Adding a new public symbol means updating BOTH
  `src/index.ts` (root barrel) AND the relevant `src/subpath/*.ts` or v3
  axis `index.ts`. Otherwise tree-shaken consumers won't see it.
  `package.json#exports` must stay aligned with the actual files.

- **Worker-thread subagent runtime (`src/runtime/worker-thread-*.ts`).**
  When a subagent has `runtime: 'worker_thread'`, it spawns a fresh V8
  isolate. Pre-flight abort short-circuits before spawn; env forwarding is
  curated (no implicit leakage). SLOs enforced by `npm run bench:worker`.
  Don't add shared globals/registries that assume a single process.

## TypeScript / module conventions

- **ESM + NodeNext.** All relative imports inside `src/` MUST end in `.js`
  (not `.ts`) — `tsc` emits as-is and Node resolves the compiled file. Do
  not introduce `tsconfig-paths` or path aliases.
- `target: ES2022`, `strict: true`, no implicit any.
- Public types live in `src/types.ts`; vendor types live in
  `src/providers/types.ts`. Don't re-export vendor SDK types from
  `src/index.ts` — keep the public surface vendor-neutral.

## Project-specific conventions

- **Generated rule files.** `clavue.md`, `AGENTS.md`, and `CLAUDE.md` are
  owned by `/init`. Durable architecture goes in this file or `docs/`.
- **Examples are documentation.** Each numbered file in `examples/` (01–31+)
  demonstrates one feature in isolation. Adding a feature → add or update
  the matching example. `npm run test:examples:live` runs them against a
  live API.
- **`docs/` is published** (in `package.json#files`). Authoritative docs
  there: `programmatic-integration-guide.md`,
  `production-agent-sdk-capabilities.md`,
  `agent-sdk-capability-upgrade-program.md`. Internal planning under
  `docs/plans/` and `docs/specs/` also ships — be deliberate.
- **`.clavue/worktrees/`** holds active agent worktrees. Treat as ephemeral;
  do not commit changes inside. The repo's `git status` often shows many
  unrelated dirty worktrees — they are not yours to clean up.
- **Surgical changes.** Fixing one provider does not mean refactoring the
  other. Adding a tool does not mean reformatting the registry.

## Environment variables

| Variable | Purpose |
|---|---|
| `CLAVUE_AGENT_API_KEY` (or `CLAVUE_AGENT_AUTH_TOKEN`) | LLM API key |
| `CLAVUE_AGENT_API_TYPE` | `anthropic-messages` or `openai-completions` |
| `CLAVUE_AGENT_MODEL` | default model id |
| `CLAVUE_AGENT_BASE_URL` | custom endpoint (proxies, OpenRouter, etc.) |
| `CLAVUE_AGENT_AUTONOMY` | `supervised`/`proactive`/`autonomous` |
| `CLAVUE_AGENT_PERMISSION_MODE` | matches `PermissionMode` union |
| `CLAVUE_AGENT_SELF_IMPROVEMENT` | `1`/`true`/`yes` to opt into run-learning |
| `CLAVUE_AGENT_JOBS_DIR` | override durable AgentJob storage dir |
| `AGENT_SDK_MAX_TOOL_CONCURRENCY` | cap for parallel read-only tool calls |

Provider tests in `tests/*provider*.test.ts` and `examples/*.ts` need these.
Most other tests (`memory`, `retry`, `tools`, `workflow-contract`,
`proof-of-work`, etc.) are pure and run offline.
